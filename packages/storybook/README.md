# Storybook host

Single Storybook instance for the monorepo. Discovers stories from every
storied workspace (`components`, `ei-app`, `echo-app`, `dpd-app`) via the
`stories` globs in [`./.storybook/main.ts`](./.storybook/main.ts).

## Running

```bash
# From repo root:
yarn storybook              # dev server on http://localhost:6006
yarn build:storybook        # static build for hosting

# Direct in this workspace:
yarn workspace storybook storybook
yarn workspace storybook test    # run Storybook tests via Vitest
```

## Story conventions

### File location

Stories live alongside their component, with the same basename:

```
packages/<workspace>/src/.../Foo.tsx
packages/<workspace>/src/.../Foo.stories.tsx
```

This Storybook discovers them through globs into each workspace, so no extra
wiring is needed when a new story is added.

### Title

`title` follows `"<Workspace>/<Folder>/<Component>"`:

| Workspace          | Title prefix       | Example                                 |
| ------------------ | ------------------ | --------------------------------------- |
| `packages/components` | `Components/...`   | `Components/FeatureAccessGuard`         |
| `packages/ei-app`     | `EI App/...`       | `EI App/Dashboard/DashboardTile`        |
| `packages/echo-app`   | `Echo App/...`     | `Echo App/Components/Foo`               |
| `packages/dpd-app`    | `DPD App/...`      | `DPD App/Pages/Bar`                     |

### Story shape

```tsx
import type { Meta, StoryObj } from "@storybook/nextjs-vite";
import { Foo } from "./Foo";

const meta = {
  title: "EI App/Components/Foo",
  component: Foo,
  parameters: { layout: "centered" },
  tags: ["autodocs"],
} satisfies Meta<typeof Foo>;

export default meta;
type Story = StoryObj<typeof meta>;

export const Default: Story = {};
```

Use the `satisfies Meta<typeof Foo>` pattern (not `as Meta<...>`) so prop
inference for `StoryObj<typeof meta>` keeps working.

Prefer `tags: ["autodocs"]` so the component gets an autogenerated Docs page
populated from its TSDoc + prop-types — the `vite-plugin-react-docgen-typescript`
plugin in `main.ts` is already configured to introspect every workspace's
`*.tsx` files.

## Mocking

Everything network-bound is mocked through [MSW](https://mswjs.io/). Do NOT
use `axios-mock-adapter` or `jest.fn()`-style patches for network calls —
those don't survive into Storybook's runtime. New endpoints get an MSW
handler in the appropriate workspace's `mocks/` directory.

### Per-story override

```tsx
import { http, HttpResponse } from "msw";

export const ErrorState: Story = {
  parameters: {
    msw: {
      handlers: [
        http.get("*/api/foo", () => HttpResponse.json({ message: "boom" }, { status: 500 })),
      ],
    },
  },
};
```

`onUnhandledRequest: "bypass"` is set globally, so unmocked requests fall
through to the real network — register a handler whenever a component you
story makes a request you don't want hitting the real backend.

## Subscription state (`useSubscription` / `FeatureAccessGuard` / `PageAccessGuard`)

Subscription entitlements are read from the Redux `billing` slice, NOT from
the network. The preview decorator defaults `billing` to a fully entitled
state (every gated page allowed, max feature limits) so any story
implicitly renders the happy path. Stories that need the gated branch
override the slice:

```tsx
import {
  entitledBillingState,
  unentitledBillingState,
} from "components/src/storybookMocks/subscriptionStoryStates";

export const Default: Story = {};            // entitled (uses the default)

export const Restricted: Story = {
  parameters: { reduxState: { billing: unentitledBillingState } },
};
```

When a story needs a specific plan in between (e.g. exercising a save-strategy
limit), spread the entitled state and override the slice fields you care
about:

```tsx
parameters: {
  reduxState: {
    billing: {
      ...entitledBillingState,
      // ... overrides ...
    },
  },
},
```

Routes the apps gate via `hasPageAccess(...)` are enumerated in
[`subscriptionStoryStates.ts`](../components/src/storybookMocks/subscriptionStoryStates.ts).
Add to that list whenever a new guarded route ships.

## Cross-workspace imports

Stories may import from any workspace, but prefer:

- **Relative imports** (`../foo`) when staying inside the file's own workspace.
- **Bare package imports** (e.g. `components`, `ei-app`) when crossing
  workspaces to a published entry point.
- The **`@/` tsconfig alias** is supported inside `ei-app`, `echo-app`, and
  `dpd-app` source files — `main.ts` registers a Vite `customResolver` that
  maps `@/foo` to the correct `packages/<app>/src/foo` based on the
  importing file's location. You can use `@/` exactly the way the apps do.
- For Storybook-side helpers and preview-only modules that may be imported
  from any workspace, prefer **relative paths** so the file stays portable
  regardless of where it's consumed.

### Watch out for barrel imports

Bare imports like `import { Foo } from "components"` pull the full
`packages/components/src/index.tsx` barrel, which re-exports the entire UI
tree including MUI. When Vite pre-bundles that path alongside the deep
imports the existing preview already uses, you can hit subtle
optimize-deps issues (e.g. `createTheme_default is not a function`).
**Prefer deep imports** — `import type { Foo } from "components/src/.../Foo"` —
in files that the Storybook preview re-imports.

## Next.js page stories (`EI App/Pages/...`)

Full routes under `packages/ei-app/src/pages/**` use a shared shell so
`useAppSelector` / `useAppDispatch` from `@/libs/redux/Store` resolve against
the **production app store** (dashboard, `walletWorthChart`, modeling slices,
etc.), not the slimmer Storybook preview store.

| Helper | Location |
| ------ | -------- |
| `withAppPageShell` | [`pageStoryDecorators.tsx`](../ei-app/src/pages/storybook/pageStoryDecorators.tsx) — `StoreProvider` + `Layout` |
| `pageRouterParams` | Same file — `parameters.nextjs.router` with no-op `push` / `replace` |
| `pageStoryHandlers()` | [`pageStoryHandlers.ts`](../ei-app/src/mocks/pageStoryHandlers.ts) — wallets, reactour, `/tokensV2` |

```tsx
import { pageStoryHandlers } from "@/mocks/pageStoryHandlers";
import {
  defaultPageParameters,
  pageRouterParams,
  withAppPageShell,
} from "./storybook/pageStoryDecorators";

const meta = {
  title: "EI App/Pages/MyPage",
  component: MyPage,
  parameters: {
    ...defaultPageParameters,
    ...pageRouterParams({ asPath: "/my-route" }),
    msw: { handlers: pageStoryHandlers() },
  },
  decorators: [withAppPageShell],
} satisfies Meta<typeof MyPage>;
```

Catch-all routes (e.g. `profile/[[...tab]].tsx`) must set `pathname` and
`query.tab` explicitly. Pages that call `useOry()` also need
`oryHandlers.whoamiAuthenticated` in `parameters.msw.handlers`.

`parameters.reduxState` only seeds the **preview** store; it does not affect
pages wrapped in `withAppPageShell`. Gated branches for `PageAccessGuard` on
pages are driven by billing data `Layout` loads via the default billing MSW
handlers into the app store — use component-level `PageAccessGuard` stories
with `unentitledBillingState` for the restricted UI.

## Adding a new story checklist

1. Create `Foo.stories.tsx` next to `Foo.tsx`.
2. Pick a `title` matching the workspace prefix (table above).
3. If the component does any of the following, follow the matching pattern:
   - Calls the network → add or extend an MSW handler.
   - Reads `state.<slice>` → pass `parameters.reduxState.<slice>` with the full slice shape.
   - Uses `useSubscription` for a gated branch → add a `Restricted` variant via `unentitledBillingState`.
4. Verify Storybook still boots clean (`yarn storybook`) and the new story renders.
